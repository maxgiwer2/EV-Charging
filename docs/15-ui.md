# 15 UI and Mobile

The interface is mobile-first because the primary moment of use is standing at
a charger with one hand free (`docs/03` → responsive/mobile-first, `docs/04`
Quick Entry and Scan).

Everything below started as a measurement in a real 375×812 viewport, not a
preference.

---

## What was measured, and what it cost

| Problem | Measured | Consequence |
|---|---|---|
| Recent-sessions table | 15 columns, 877px wide in a 359px container | **518px of every row off screen** — the totals people opened the app for were the hidden part |
| Tap targets | nav, export and filter links **17–21px tall** | WCAG 2.5.5 and Apple's HIG both want ~44px; below that misses are frequent |
| Primary action | "+ Add" was a 17px link at the top of an ~1800px page | The most-used action was the hardest to reach |
| Header | 6 inline links + name + sign-out at 375px | Wrapped onto two rows, 75px of vertical space before any content |
| Form fields | rendered 23px tall at <16px font | Small targets, and iOS Safari zooms the page on focus below 16px |

## What changed

### Navigation

Two presentations of one definition — the `$nav` array in the layout — so they
cannot drift apart.

- **Phone:** a fixed bottom tab bar (Dashboard, Receipts, **+**, Vehicles,
  Budgets). Each tab is 56px. The add button is a 56px circle in the centre,
  where a thumb rests.
- **Desktop (`md+`):** the horizontal bar, with the bottom bar hidden.
- Account details and sign-out moved into a menu behind an avatar button, which
  keeps the header to one row.

`viewport-fit=cover` plus `pb-[env(safe-area-inset-bottom)]` keeps the bar clear
of the home indicator on notched phones.

### Lists

Every table now has a card equivalent shown below `md`:

| Screen | Mobile | Desktop |
|---|---|---|
| Recent sessions | Card: date, amount, station, then kWh / km / cost-per-kWh | 15-column table |
| Receipts | Full-row link with status and duplicate badge | Table with a Review action |
| Vehicles | Card with battery, session count, Edit/Remove buttons | Table |

The card shows the four facts worth scanning; the table keeps everything for a
screen wide enough to hold it. Nothing was removed — only re-prioritised by
viewport.

### Dashboard hierarchy

Total spend is now a single large figure with its comparison, above a 2-column
grid of the derived metrics. Previously it was one tile among eight, all equal
weight. Period selection and exports moved into a disclosure, since they are
occasional actions that were pushing the figures below the fold.

### Forms

A single rule in `app.css` sizes every control at `min-height: 2.75rem` and
`font-size: 16px` below `md`. Done centrally so a form added later cannot miss
it. Checkboxes and radios keep their intrinsic size — stretching them looks
broken and their labels carry the tap area.

Money inputs carry `inputmode="decimal"` for a numeric keypad, and the receipt
upload uses `capture="environment"` so "Scan" opens the camera.

---

## Verified

All eight authenticated screens at 375×812: **no horizontal overflow, no tap
target under 44px, no table rendered on mobile.** At 1265px the desktop nav and
the 15-column table return and the bottom bar is hidden.

`tests/Feature/Web/MobileLayoutTest.php` asserts the structural decisions — a
headless test cannot see pixels, so it checks the responsive classes,
`inputmode`, `capture`, the safe-area opt-in and, importantly, that the figures
are unchanged by the redesign.

## A trap worth remembering

During this work every page rendered unstyled for a while. The cause was a
stale `public/hot` file: it makes `@vite` point at the Vite dev server, so with
no dev server running **no CSS loads at all**. It is gitignored, so it only ever
affects a local checkout. If the app appears completely unstyled, delete
`public/hot` and re-run `npm run build`.

## Not done

- No dark mode. Worth adding, but it doubles the surface to check and none of
  the measured problems above were about contrast.
- Colour still carries meaning in the budget bar and the status pills. Each is
  paired with a number or a word, so no information is colour-only, but a
  formal contrast audit has not been run.
- The bar chart is CSS only, with values in `title` attributes. That is fine for
  one series and keeps the strict `script-src` CSP, but it is not reachable by
  keyboard.
